# Command (Команда)

**Область:** Behavioral / GoF

---

## Смысл паттерна

**Command** инкапсулирует **запрос как объект**. Вместо прямого вызова `receiver.doSomething()` клиент создаёт команду с методами `execute()` и (опционально) `undo()`, передаёт её **Invoker**'у и тем самым отделяет «кто инициирует» от «что делается».

Команда хранит ссылку на **Receiver** (объект, который реально выполняет работу) и параметры операции. Это открывает:

- **очередь** и отложенное выполнение;
- **историю** и отмену (undo/redo);
- **логирование** и макросы (составные команды);
- единый интерфейс для разных действий (кнопки, hotkeys, CLI).

```
Invoker → Command.execute() → Receiver
                ↑ undo()
           History stack
```

---

## Как устроено демо

В `command.js` — классический пример «умного пульта» и лампы:

| Роль | Класс |
|------|-------|
| Receiver | `Light` — `turnOn()` / `turnOff()`, поле `on` |
| Command | `LightOnCommand`, `LightOffCommand` — делегируют в `Light` |
| Invoker | `RemoteControl` — `press(command)`, `undo()` через стек `history` |

Сценарий демо:

1. `remote.press(on)` — лампа включается, команда в истории.
2. `remote.press(off)` — выключается.
3. `remote.undo()` — откатывается последняя команда (`off.undo()` → снова `on`).

Базовый `Command` задаёт контракт `execute()` / `undo()` с заглушками, подклассы переопределяют оба метода симметрично.

---

## Когда применять

- Нужны **undo/redo**, история операций, транзакционный UI (редакторы, CAD, игры).
- Действия ставятся в **очередь** или выполняются асинхронно / по расписанию.
- Один Invoker должен вызывать **разные операции** через единый интерфейс (toolbar, macro recording).
- Нужно **логировать или сериализовать** действия пользователя.

**Не стоит** для простых одноразовых вызовов без отмены и очереди — прямой вызов метода проще.

---

## Связь с другими паттернами

| Паттерн | Отличие |
|---------|---------|
| **Strategy** | Меняет *алгоритм*; Command — *действие* с возможностью отмены и истории |
| **Memento** | Сохраняет *состояние*; Command — *операцию* над состоянием |
| **Chain of Responsibility** | Маршрутизирует запрос; Command — упаковывает его в объект |
| **Composite Command** | Несколько команд как одна (макрос) — частый надстрой над Command |

---

## Краткий итог

Command = **объект-запрос** с `execute` / `undo`, связывающий Invoker и Receiver. Invoker не знает деталей операции — только вызывает команду. В демо пульт накапливает историю нажатий и откатывает последнее действие.
