# Mediator (Посредник)

**Область:** Behavioral / GoF

---

## Смысл паттерна

**Mediator** централизует **взаимодействие между объектами-коллегами**. Вместо сети «каждый с каждым» (N×N связей) коллеги знают только посредника; маршрутизация, broadcast и правила доставки живут в одном месте.

Это уменьшает связность: добавить участника или изменить протокол общения — править Mediator, а не все пары классов.

```
Без Mediator:  A ↔ B, A ↔ C, B ↔ C  (много связей)
С Mediator:    A → M ← B, C         (звезда)
```

---

## Как устроено демо

В `mediator.js` — **чат-комната**:

| Класс | Роль |
|-------|------|
| `ChatMediator` | Абстракция: `send()`, `addUser()` |
| `ChatRoom` | Конкретный посредник: реестр `users`, маршрутизация |
| `User` | Colleague: шлёт через `mediator`, получает `receive()` |

Поток сообщений:

1. `room.addUser(alice|bob|carol)` — пользователь регистрируется, получает ссылку на комнату.
2. `alice.send("Hi Bob!", "Bob")` → `ChatRoom.send` → `bob.receive(...)`.
3. `bob.sendAll("Hello everyone")` → `ChatRoom.broadcast` → все, кроме отправителя.

`User` не держит прямых ссылок на других пользователей — только на `mediator`.

---

## Когда применять

- Много объектов **обмениваются сообщениями**, и прямые ссылки дают спагетти-зависимости.
- Логика координации **сложная** (очереди, приоритеты, группы, права) — её проще держать в одном Mediator.
- UI-формы с взаимозависимыми виджетами (поле A блокирует B при значении C).
- Чат, event bus, dialog coordinator, air traffic control — типичные метафоры.

**Не стоит**, если Mediator превращается в **God object** на тысячи строк — тогда деком-pose на под-координаторы или явные bounded contexts.

---

## Связь с другими паттернами

| Паттерн | Отличие |
|---------|---------|
| **Observer** | Subject уведомляет подписчиков; Mediator — *двусторонняя* координация и маршрутизация |
| **Facade** | Упрощённый вход в подсистему; Mediator — *протокол* между равноправными коллегами |
| **Event Bus / Pub-Sub** | Практическая разновидность Mediator в frontend/backend |
| **Chain of Responsibility** | Линейная передача запроса; Mediator — центральный hub |

---

## Краткий итог

Mediator = **звезда вместо mesh-сети**: коллеги общаются только через посредника. В демо `ChatRoom` доставляет личные и broadcast-сообщения, а `User` остаётся простым отправителем/получателем без знания остальных участников.
