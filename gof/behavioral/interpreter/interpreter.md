# Interpreter (Интерпретатор)

**Область:** Behavioral / GoF

---

## Смысл паттерна

**Interpreter** задаёт **грамматику простого языка** как дерево объектов и вычисляет («интерпретирует») выражения через общий метод — в демо это `interpret(context)`.

Каждый класс выражения отвечает за один синтаксический элемент: переменная, AND, OR, NOT. Сложное предложение собирается **композицией** узлов; контекст (`{ a: true, b: false, … }`) подставляет значения переменных.

Паттерн уместен, когда:

- язык **маленький и стабильный** (правила, фильтры, формулы);
- часто добавляются **новые конструкции грамматики**, а не новые операции над уже существующими узлами.

```
Expression tree → interpret(context) → boolean / number / …
```

---

## Как устроено демо

В `interpreter.js` — **булева алгебра** с переменными:

| Класс | Смысл |
|-------|-------|
| `Expression` | Абстракция с `interpret(context)` |
| `Variable` | Читает `context[name]` как boolean |
| `And`, `Or`, `Not` | Комбинируют дочерние выражения |

Дерево для демо: `(a AND b) OR (NOT c)`:

```js
new Or(
  new And(new Variable("a"), new Variable("b")),
  new Not(new Variable("c"))
);
```

Три вызова `interpret()` с разным контекстом дают `true`, `false`, `true` — видно, как одно дерево переиспользуется с разными привязками переменных.

---

## Когда применять

- Доменный **мини-язык**: правила скидок, ACL-выражения, search filters, конфиг-условия.
- Грамматика **простая**, дерево разбирается и интерпретируется без тяжёлого парсера.
- Новые **синтаксические конструкции** добавляются новыми классами `Expression`.

**Не стоит** для полноценных языков программирования — лучше parser + AST + visitor или готовый DSL-движок. Если часто добавляют **новые операции** над одними и теми же узлами — уместнее **Visitor**.

---

## Связь с другими паттернами

| Паттерн | Отличие |
|---------|---------|
| **Composite** | Тоже дерево; Interpreter добавляет семантику `interpret()` |
| **Visitor** | Новые *операции* над AST без новых классов узлов |
| **Strategy** | Один алгоритм на выбор; Interpreter — *грамматика* целиком |
| **Parser / AST** | Interpreter часто следует за разбором текста в дерево выражений |

---

## Краткий итог

Interpreter = **грамматика как объектное дерево** + единый метод вычисления. Каждый узел знает, как интерпретировать себя в контексте переменных. В демо — компактный булев DSL без парсера строк: дерево собирается в коде вручную.
