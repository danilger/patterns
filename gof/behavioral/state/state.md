# State (Состояние)

**Область:** Behavioral / GoF

---

## Смысл паттерна

**State** позволяет объекту **менять поведение** при смене внутреннего состояния. Вместо больших `if/switch` по enum'у Context **делегирует** вызовы текущему объекту State; переходы между состояниями оформлены в самих классах состояний.

Каждое состояние инкапсулирует реакцию на одни и те же методы (`play`, `pause`, `stop`) по-разному. Context хранит ссылку на `state` и проксирует вызовы.

```
Context.play() → currentState.play() → setState(new …State)
```

---

## Как устроено демо

В `state.js` — **аудиоплеер** с тремя состояниями:

| State | Поведение |
|-------|-----------|
| `ReadyState` | `play` → Playing; `pause`/`stop` — no-op с сообщением |
| `PlayingState` | `pause` → Paused; `stop` → Ready |
| `PausedState` | `play` → resume Playing; `stop` → Ready |

`AudioPlayer` (Context) создаётся в `ReadyState`, методы `play/pause/stop` делегируют в `this.state`.

Демо-цепочка:

```
play → pause → play → stop → pause
```

Лог в консоли показывает, что одна и та же кнопка `play` в Ready, Playing и Paused означает разное — «Start», «Already playing», «Resume».

---

## Когда применять

- Объект ведёт себя **по-разному в зависимости от режима** (FSM: draft/published, connected/disconnected, playing/paused).
- Условная логика раздувается **switch по state + event**.
- Переходы **явные и локализованы** в классах состояний (легче тестировать, чем монолитный switch).

**Не стоит** для 2–3 тривиальных флагов — достаточно enum + простые guard'ы. Если состояний десятки с общей таблицей переходов — иногда удобнее **state machine library** или таблица переходов.

---

## Связь с другими паттернами

| Паттерн | Отличие |
|---------|---------|
| **Strategy** | Меняет *алгоритм* по выбору клиента; State — *режим* с автоматическими переходами |
| **Command** | Инкапсулирует действие; State — *контекст*, в котором действие допустимо |
| **Memento** | Сохраняет данные; State — *поведение* при текущем режиме |
| **State Machine (XState и др.)** | Формализация того же подхода с диаграммами и guards |

---

## Краткий итог

State = **поведение в отдельных классах состояний**, Context только держит текущее и делегирует. Переходы происходят внутри state-объектов через `player.setState(...)`. В демо плеер проходит цикл Ready → Playing → Paused без единого switch.
