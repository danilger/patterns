# Iterator (Итератор)

**Область:** Behavioral / GoF

---

## Смысл паттерна

**Iterator** даёт **последовательный доступ** к элементам агрегата **без раскрытия его внутренней структуры**. Клиент обходит коллекцию через единый интерфейс (`hasNext` / `next` или `for…of`), не зная, массив это, связный список или дерево.

Разделяются две роли:

- **Aggregate** — хранит данные и создаёт итератор;
- **Iterator** — инкапсулирует позицию обхода и способ получения следующего элемента.

Несколько итераторов могут независимо обходить одну коллекцию; можно подменить алгоритм обхода (вперёд, назад, фильтрованный) без смены клиентского кода.

---

## Как устроено демо

В `iterator.js`:

| Класс | Роль |
|-------|------|
| `Iterator` | Контракт `hasNext()` / `next()` |
| `ArrayIterator` | Обход массива по индексу |
| `WordsCollection` | Aggregate: `add()`, `createIterator()` |

Демо в двух части:

1. **Классический итератор** — `while (iterator.hasNext())` печатает `first`, `second`, `third`.
2. **Нативный JS** — у коллекции есть `[Symbol.iterator]()`, поэтому работает `[...words]` и `for…of`.

Это показывает связь GoF-итератора с протоколом iterable в современном JavaScript: идея та же, API — `Symbol.iterator` + generator или встроенный итератор массива.

---

## Когда применять

- Нужно **скрыть** внутреннее представление коллекции (дерево, граф, кастомный буфер).
- Требуются **разные способы обхода** одной структуры (DFS/BFS, постраничный, lazy).
- Обход должен быть **ленивым** — элементы вычисляются по мере запроса.
- Несколько **независимых курсоров** по одной коллекции.

**Не стоит** для простого массива в JS, если достаточно `for…of` / `.map()` — встроенный iterable уже реализует паттерн.

---

## Связь с другими паттернами

| Паттерн | Отличие |
|---------|---------|
| **Composite** | Структура «часть–целое»; Iterator — *обход* структуры |
| **Visitor** | Операции над элементами; Iterator — *доступ* к элементам |
| **Factory Method** | `createIterator()` часто фабрика итераторов под тип коллекции |
| **Cursor / Generator** | Современные языковые формы того же приёма |

---

## Краткий итог

Iterator = **отделить «как хранится» от «как обходится»**. Клиент знает только `hasNext`/`next` или iterable-протокол. В демо коллекция слов отдаёт классический итератор и одновременно поддерживает spread/`for…of` через `Symbol.iterator`.
