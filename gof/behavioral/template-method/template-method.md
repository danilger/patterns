# Template Method (Шаблонный метод)

**Область:** Behavioral / GoF

---

## Смысл паттерна

**Template Method** задаёт **скелет алгоритма** в базовом классе: порядок шагов фиксирован, отдельные шаги переопределяют **подклассы**. Инвариантная структура (`mine`, `open`, `parse`, `analyze`, `send`) остаётся в одном месте; вариативность — в hooks и abstract steps.

Это **наследование + инверсия**: родитель вызывает дочерние методы (Hollywood Principle: «не вызывай нас — мы вызовем тебя»).

```
TemplateMethod() {
  step1();      // общий или abstract
  step2();      // abstract в подклассе
  hook();       // опциональный override
}
```

---

## Как устроено демо

В `template-method.js` — **извлечение данных из файлов**:

| Элемент | Где |
|---------|-----|
| Template method | `DataMiner.mine(path)` — фиксированная последовательность |
| Общий шаг | `openFile`, `analyze` — реализация в базе |
| Abstract steps | `extractData`, `parseData` — в подклассах |
| Hook | `sendReport` — можно переопределить (`CsvMiner` шлёт email-лог) |

Подклассы:

- **`PdfMiner`** — свои `extractData` / `parseData` для PDF-подобного контента.
- **`CsvMiner`** — другой parse + кастомный `sendReport`.

Демо вызывает `pdf.mine("doc.pdf")` и `csv.mine("data.csv")` — один pipeline, разные детали на шагах extract/parse/report.

---

## Когда применять

- Несколько классов делят **один и тот же workflow**, но отличаются **отдельными шагами** (ETL, lifecycle hooks, build pipelines).
- Порядок шагов **критичен** и не должен дублироваться в подклассах.
- Нужны **optional hooks** (логирование, валидация) с дефолтом в базе.

**Не стоит**, если вариативность только в **одном алгоритме целиком** — лучше **Strategy**. Если иерархия наследования нежелательна — composition + pipeline функций.

---

## Связь с другими паттернами

| Паттерн | Отличие |
|---------|---------|
| **Strategy** | Композиция: алгоритм *подставляется*; Template Method — *наследование* фиксированного скелета |
| **Factory Method** | Создание объекта; Template Method — *последовательность операций* |
| **Hook method** | Частный случай optional step в Template Method |
| **Pipeline / Middleware** | Композиционный аналог фиксированного порядка шагов |

---

## Краткий итог

Template Method = **алгоритм в базовом классе, детали в подклассах**. `mine()` не переопределяется — меняются только шаги внутри. В демо PDF и CSV проходят один pipeline добычи данных с разным extract/parse и разной отправкой отчёта.
