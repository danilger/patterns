# Adapter (Адаптер)

**Область:** GoF / Structural

---

## Смысл паттерна

**Adapter** преобразует **интерфейс одного класса** в интерфейс, который **ожидает клиент**, не меняя исходный код адаптируемого класса.

Классический сценарий: legacy-библиотека с методом `startPlayback(path, volume)`, а приложение работает только с `play(filename)`. Адаптер переводит вызовы между двумя несовместимыми API.

---

## Как устроено демо

В `adapter.js` используется **Object Adapter** (композиция):

1. **`MediaPlayer`** — целевой интерфейс (`play(filename)`).
2. **`Mp3Player`** — «родная» реализация Target.
3. **`LegacyAudioApi`** — Adaptee с чужим API `startPlayback(path, volume)`.
4. **`AudioAdapter`** — держит `legacyApi`, в `play()` вызывает `startPlayback` с `defaultVolume`.
5. **`playTrack(player, filename)`** — клиент принимает любой `MediaPlayer`.

Демо проигрывает трек через нативный MP3-плеер и через адаптированный legacy API — один и тот же клиентский код.

---

## Когда применять

- Нужно **подключить стороннюю библиотеку** без правки её исходников.
- Старый и новый код **не совместимы по сигнатурам**, но семантика близка.
- Хотите **изолировать** legacy за тонким слоем перевода.
- Интеграция SDK, где контракт вендора **не совпадает** с доменной моделью приложения.

## Когда не стоит

- Проще **изменить интерфейс** у одной из сторон (вы контролируете оба модуля).
- Адаптер превращается в **God Object** с сотнями методов-прокси.
- Нужно не перевод интерфейса, а **новая абстракция** над двумя ветками — смотри Bridge или Facade.

---

## Связь с другими паттернами

- **Facade** — упрощает **подсистему**; Adapter — **совместимость интерфейсов** двух объектов.
- **Bridge** — разводит абстракцию и реализацию заранее; Adapter — **постфактум** стыкует чужие API.
- **Decorator** — расширяет поведение с **тем же** интерфейсом; Adapter **меняет** контракт.

---

## Краткий итог

Adapter = **переводчик между интерфейсами**. В демо `AudioAdapter` оборачивает legacy API и выдаёт его клиенту как обычный `MediaPlayer`.
